# 68040 MMU translation engine

The internal engine in `src/runtime/mmu040.c` implements the translation and
descriptor-bus portion of the MC68040 MMU. Its reference is Motorola's
[MC68040 User's Manual, chapter 3](https://www.nxp.com/docs/en/reference-manual/MC68040UM.pdf),
especially figures 3-8 through 3-12 and sections 3.3, 3.4 and 3.7. It is original
code; no emulator implementation was imported.

This is an integration component, not enabled ROMAW guest paging. It is built into
`libsyn68k.a`. ROMAW's ordinary CPU memory operations, native blocks, instruction
fetches, exception stacks and host pointers use the existing flat memory system;
that path rejects guest MMU enables. The explicit mapped backend supplies logical
instruction/operand/exception buses and directly lowered FPU and MMU execution
through its supplied engine. This does not enable ROMAW-wide guest paging or
claim Mac OS MMU/virtual-memory compatibility.

The current FPU physical/ATC cleanup and restart contract is documented in
[68040 writeback recovery](68040-writeback-recovery.md).

The separate `cache040.c` physical cache component is under integration.
`Syn68kMMU040Memory.cache` optionally binds caller-owned cache storage, a live
CACR and a physical cycle bus. Normal operands, instruction fetch and table
searches then use the same cache policies in checked and closed native code.
With a NULL binding, the operand boundary remains uncached or owned by its
embedding implementation. CPU cache instructions and cache-push/fill exception
frames are still unfinished. See the current
[compatibility checkpoint](68040-status.md) for the component and open bindings.

The cache component distinguishes exception, descriptor and locked transfers,
including descriptor WT/no-allocation, disabled-cache descriptor lockup and
locked-hit push/invalidation. Its typed physical cycles retain push identity
and LOCK/LOCKE intent. Descriptor operands retain their original table callbacks;
locked U-bit updates push/invalidate first and then use the original atomic
update. Native permanent RAM handles both stages inside the emitted image.
Merely supplying the existing MMU bus does not activate the cache binding.
Access results retain cache failures and their captured line/cycle separately
from the original logical operand's restart state. PTEST retains ordinary table
bus failures as diagnostics, while cache-push/lockup failures preserve MMUSR
and remain visible to the CPU. Those failures still need their complete frame
or halt handling. Exception entry uses no-allocation cache traffic.

Table callbacks return positive success, zero for a logical table-bus error,
or a negative physical-abort status. Physical aborts leave ATC publication and
PTEST MMUSR updates uncommitted, preserving live callback changes. Native RAM
adapter fallbacks preserve the signed status for both reads and updates.

Run `bash syn68k/tests/check-core.sh mmu040-cache` for the reference binding
matrix and `native040` for the emitted callback/permanent-RAM variants.
The mapped CPU cache probe is grouped with `rte` and cold/warm `aot-x64`.

Mapped MOVEM loads and stores now use CM/saved-EA restart for all legal
addressing modes. Stores additionally retain the failed scalar in WB1/WB2 for
guest cleanup before list replay; further instruction-fetch faults retain CM
without a pending write. See the current
[68040 compatibility checkpoint](68040-status.md) for validation and remaining
restart work. The store suite includes partial ATC faults and active A7 recovery.
Historical audit entries below describe their
earlier implementation limits.

MOVE16 write faults retain complete PD0-3 line data. Physical failures retire
postincrements and use WB1; certified ATC aborts use WB2 and permit guest retry
or captured-line cleanup/skip. Entry T1 is retained through physical cleanup/RTE.
The scalar bus boundary and remaining block-bus limits are documented in
[the current compatibility checkpoint](68040-status.md).

MOVE16 read aborts retain original PC/registers and expose the original source
burst address with line-sized normal read status and no pending writes. Guest
repair/RTE retries the complete source line; successful partial reads are
repeated. Callback state changes deny certification without rollback. The
physical block/cache bus remains outside the scalar callback boundary.

## Implemented behavior

Mapped forced exceptions retain instruction-entry T1 and deliver the forced
frame/vector before a format-2 trace frame. Trace precedes forced-handler
execution and pending interrupts. Two guest RTEs unwind the frames. Delivery
faults preserve completed writes and use the existing access-fault result;
embedding code remains responsible for double-fault recovery. See the current
compatibility checkpoint for the tested classes and exclusions.

- Three-level 4K/8K table searches using separate supervisor and user roots,
  including one indirect page-descriptor level and both resident encodings.
- Accumulated write protection, supervisor-only pages, used/modified updates
  and full physical address/attribute results.
- Separate instruction/data TTR pairs, masked high-byte matching, FC2 matching,
  TT0 priority, write protection and cache/user attributes. TTRs remain active
  with paged translation disabled.
- Separate four-way, 16-set instruction/data ATCs, privilege tags, cached invalid
  translations and a two-bit replacement counter per bank. A permitted write
  to an M-clear hit searches again, including newly changed mappings/permissions.
- Page/all flushes with privilege and global-entry qualification. PTEST refreshes
  the selected ATC bank/privilege and updates MMUSR, including table-bus errors.
- Control-register masks and warm-reset behavior. Root/control writes and reset
  do not flush ATCs; reset disables TCR/TTR enables while retaining page size.

The mapped CPU also executes STOP through checked stepping and a closed native
status root. It loads SR/CCR and the selected stack bank, retains its following
PC, and reports `SYN68K_MAPPED_STOPPED` without fetching another instruction.
Instruction-entry trace suppresses suspension. A newly eligible pending
interrupt reports `SYN68K_MAPPED_INTERRUPT`; accepted exception entry clears
the stopped latch, and the guest handler/RTE resumes execution. Reset owners
explicitly clear `Syn68kMappedCPU.stopped`. Zero budget reports BUDGET while
preserving the latch. STOP fields extend the internal step/CPU records, so
callers must rebuild. See [the current validation checkpoint](68040-status.md).

Ordinary FCs are 1, 2, 5 and 6. Other three-bit FCs bypass translation. MOVES
must convert instruction-space SFC/DFC values to data references before calling
this engine, as specified by the manual's table 3-2. Operand faults in alternate
spaces carry TT=2 and their original TM; FC2/6 MOVES faults carry converted data
TM. Contradictory alternate-space ATC records are rejected. Invalid host requests return
`MMU040_BAD_REQUEST`; a bad PTEST request leaves MMUSR unchanged.

PTEST with TC.E clear and no TTR hit selects zero for architecturally undefined
MMUSR contents; PTEST with FC 0, 3, 4 or 7 likewise selects zero for its
undefined result. PTEST faults are diagnostic results for MMUSR, not operand
exceptions to deliver to the guest. Page-size changes require an explicit flush; omitted-flush
behavior across different page sizes is not a conformance claim.

## Physical-bus contract

The engine never dereferences guest pointers. `read32` receives a physical
descriptor address and returns a host-order value from big-endian guest memory.
`update32` requests either a full descriptor write or a locked read/OR/write to
set U. The embedding bus owns synchronization and reports failures without
partially publishing a descriptor. The single-threaded test bus records these
requests; it does not validate concurrent bus arbitration or physical signals.

Callback order follows figure 3-10: a table descriptor's pending U write occurs
after reading its successor, including when that successor read fails. Completed
history updates survive a later failure. U-only page updates request locked RMW;
a first permitted write with M clear requests a descriptor write setting U/M.
Write-protect/supervisor failures never newly set M. Bus errors produce B-only
PTEST status and retain the failed descriptor address for diagnostics.

`translate` returns one logical-address translation, permission result and
attributes. It does not read/write the requested operand, validate every page
of a multi-byte span, emulate physical caches or deliver CPU exceptions.
Ordinary translation leaves MMUSR unchanged. A caller must check `fault` before
using the physical address, split cross-page accesses and apply the attributes
at the physical memory/device boundary.

## Logical operand boundary

`src/runtime/mmu040-memory.c` combines the translation engine with separate
physical operand callbacks. It supports byte, word and longword reads/writes,
splitting at page boundaries and at the 32-bit address wrap. Adjacent logical
pages need not have contiguous physical addresses. Each callback receives the
translation attributes and a big-endian byte buffer, never a guest host pointer.
Instruction/data selection and privilege are explicit function codes.

A read-modify-write read requests write permission and sets M before its operand
read. The embedding CPU/bus must provide atomicity across the read/write pair.
By default callbacks operate on page chunks. Setting
`Syn68kMMU040Memory.aligned_transfers` to one selects an uncached physical bus
boundary: each callback transfers a naturally aligned byte, word or longword
(MC68040UM 7.3). An odd longword uses byte/word/byte transfers, and an odd word
uses two byte transfers. Both checked and directly lowered native execution use
this policy. Zero preserves the operand boundary for embeddings that own cache
or device decomposition; other values are rejected before bus access. This does
not implement cache fills, timing or CPU writeback recovery.
Callbacks complete a whole chunk or fail without publishing that chunk. A fault
on a later chunk preserves earlier operand writes and descriptor U/M updates;
the result records the failed chunk's logical address and completed byte count.
Read output is published only after the whole requested operand succeeds.

Access results retain the original scalar address, FC, size, direction and RMW
intent, as well as the width-limited write value or successfully read prefix.
`syn68k_mmu040_write_rmw` retains locked-transfer intent for the write portion.
The physical bus/CPU still owns atomicity across the pair.

`syn68k_mmu040_access_ssw` supplies the basic MA/ATC/LK/RW/SIZE/TM fields from
MC68040UM section 8.4.6.2. Translation/table-search failures set ATC; physical
operand bus failures do not. MA marks a second-page ATC fault, rather than every
partial transfer. Successful or invalid host requests do not fabricate status
words. Continuation, trace, cache-push and writeback state remain CPU work;
these fields alone are not a complete format-7 frame or restart implementation.

This boundary is also an internal component: Global CPU execution has not yet been
routed through it. Its partial-access metadata is not a format-7 restart frame.

## Bounded effective-address integration

An explicit `Syn68kEAContext` can now supply the mapped operand boundary. Its
extension fetches use instruction FCs, while PC-relative operands and indexed
memory-indirect pointer reads use data FCs. Immediate sources retain their
instruction-space identity. Explicit FC and RMW-intent helpers preserve alternate
access identity, and faults retain the failed logical chunk, MMU status and
completed-byte count. A failed context stops further accesses.

The terminal integer decoders now distinguish extension fetches from operand
reads; MOVES normalizes SFC/DFC to data FCs explicitly. Production contexts still
select flat memory. The FPU mapped stepping boundary is described below.

The Windows archive-linked suite includes 71 mapped EA cases: privilege and
instruction/data ATC separation, immediate versus PC-relative sources, full
indexed indirection, explicit FC overrides, registers, split fetch/write faults,
RMW protection and physical operand failures. The existing flat EA, full control
register/integer addressing and FPU dispatch checks also pass in both runtime
modes where applicable. These are component/flat execution checks, not mapped
whole-program execution or physical 68040 measurements.

## Mapped FPU instruction stepping

`include/fpu.h` exposes an internal, serialized `syn68k_fpu_step` boundary. It
executes an actual FPU instruction using an explicit logical-memory bus and
returns the next PC or exception metadata. Opcode/extension/immediate reads use
instruction FCs; operands, indexed indirection and FSAVE/FRESTORE frames use data
FCs. Extended-format sources also access the unused word in their 96-bit memory
representation, without using its value in arithmetic.

All FPU memory accesses now use bounded EA helpers. Multiword mapped transfers
retain completed writes before a later fault. Failed reads do not publish a
partial floating-point register, and a failed FRESTORE leaves its postincrement
and FPU state uncommitted. Flat multiword stores retain their whole-span bounds
checks. The regular dispatcher uses this same stepping code with flat memory,
then performs its existing exception delivery.

The mapped caller owns alignment checks, code-cache coherence and exception
stack/restart handling. Returned `access` metadata describes the failed scalar
subtransfer, not the cumulative progress of a frame or extended operand. The
reported format/exception PC follow the existing flat dispatcher; they do not
constitute a complete hardware format-7 continuation/restart implementation.
No mapped exception is sent through the flat stack-writing path by this API.

The archive-linked Windows probe passes 295,765 mapped cases. It exercises every
4K/8K page offset for six supported numeric load/store formats in both privilege
modes, split immediate instructions, 52/100-byte real FPU state frames, opcode
and operand faults, unused-word checks, partial saved frames, and failed
postincrement restores. Flat interpreter/native FPU dispatch and 100 independent
QEMU value/condition comparisons per mode also pass. Packed decimal arithmetic
and general MMU execution are not claimed by these tests.

## Mapped integer arithmetic stepping

The internal `integer.h` stepping boundary shares the real word/long
MULU/MULS/DIVU/DIVS implementations with ordinary dispatch. Explicit mapped
callers route opcode, extension, immediate, indirect and operand reads through
the logical-memory bus. Faults return vector/format/PC and scalar access
metadata without constructing a flat exception stack; divide-by-zero retains
its post-instruction PC and format-2 instruction address. Flat dispatch keeps
its existing vector and stack delivery. This is a serialized component step,
not a mapped whole-program dispatcher, and does not enable guest TC/TTR writes.
The remaining work below still applies to other instructions and native code.

The archive-linked Windows suite passes 295,528 cases, including every 4K/8K
operand-page offset for the twelve signed/unsigned word/long multiply/divide
forms in both privilege modes. It checks disjoint physical pages, immediate
fetches crossing code pages, opcode/extension/operand failures, partial reads,
physical bus faults, reserved encodings, zero divisors and all supported EA
families except absolute word. Dn, indirect, predecrement/postincrement, signed
displacement, brief/full indirection, absolute long and PC-relative sources
execute through the real shared arithmetic helpers. These are mapped component
checks, not physical 68040 restart measurements.

MOVEM uses the same stepping boundary for word/long register lists, with mapped
mask/EA fetches and scalar data transfers. It preserves completed registers,
stores and address updates before a later fault; a scalar split store can
publish its first page before the second page fails. Returned access metadata
describes that scalar transfer, not the aggregate list. Mapped callers own
physical code-cache coherence; flat stores retain their existing invalidation.
The additional 721,036-case fixture checks every mask with ordinary/automatic
loads/stores, both widths, every page offset in both privilege modes, base-list
aliases, partial translation/bus failures, mask-fetch faults and code overwrite.
These preserve the bounded runtime contract, not precise physical 68040
writeback/continuation or exception-stack behavior.

MOVES also shares the stepping boundary. Opcode, extension and EA-indirect
reads retain the executing privilege's normal FCs; the final operand uses
SFC/DFC, with FC 2/6 normalized to data FC 1/5 as on the 68040. Mapped bypass
FCs reach the caller's device bus unchanged. The flat bus still faults spaces
without a device mapping. The 296,112-case fixture checks every 4K/8K page
offset for normal spaces, all register fields and update modes, width/sign
rules, partial translation/physical faults, privilege/reserved errors and
distinct bypass banks. The existing 39,936-case flat fixture checks ordinary
execution. Precise restart and mapped exception-stack delivery remain unfinished.

JSR/JMP/LEA/PEA now share the same boundary. Address formation uses mapped
extension and indirect reads without fetching the target. JSR/PEA push through
the mapped data bus, retaining completed bytes and the decremented SP on a
later fault. Mapped calls do not populate the flat return cache. The 49,298-case
fixture checks addressing forms, signed absolute words, split instruction
extensions, every stack-page offset, A7 aliases, condition-code preservation
and physical/translation stack faults. It returns the next logical PC; it does
not execute a mapped block, deliver target alignment faults or build restart
frames. Flat dispatch retains its existing PC cleaning and return caching.

MOVEP uses mapped displacement fetches and separate byte operands at sparse
addresses. A failed load leaves Dn uncommitted; stores retain all successful
earlier bytes. The returned access record describes the failing byte. The
99,432-case fixture checks every 4K/8K offset in both privilege modes, both
widths/directions, register fields, negative displacement, sparse translation
and physical failures, instruction fetch faults and code/displacement overwrite.
Ordinary execution continues through the same helper and its unchanged
115,144-case flat fixture. This preserves the bounded runtime policy; precise
hardware continuation/writeback remains outside this stepping interface.

## Remaining execution integration

The integer stepping boundary now shares the ordinary scalar memory and
complex-integer kernels with flat execution. MOVE/MOVEA, memory arithmetic,
logic, quick/unary/bit operations, conditions, memory shifts, decimal/pack,
CAS/CAS2 and bitfields route their operands and live extensions through the
supplied mapping context. Mapped stores leave physical code-cache coherence to
the caller instead of invalidating unrelated flat logical blocks. Failures
return exception/access metadata without entering the flat exception stack.
CAS/CAS2 and TAS use write-permission-checked locked reads and preserve RMW
intent on mapped writes; the embedding physical bus still owns lock arbitration.

The additional Windows fixture compares 10,784 mapped cases with independent
synthetic execution across disjoint code/data pages, both page sizes and both
privilege modes. It includes split-page partial reads/stores and read-only
CAS/TAS faults. The same kernels compile with the x64 JIT disabled. This expands
component stepping; the stream backend below builds on it. ROMAW guest
paging remains gated.

Common register forms now use the same stepping boundary: MOVE/MOVEA/MOVEQ,
arithmetic/logic/immediates, ADDA/SUBA/CMPA, ADDX/SUBX, unary operations,
SWAP/EXT/EXG, bit operations, Scc, CCR transfers and every register shift/count.
Immediate CCR operations fetch their words through instruction space. The
expanded differential fixture passes 80,672 cases, including zero/maximum shift
counts and boundary values. EXTB.L is kept separate from the LEA opcode family.

Mapped control stepping now includes all Bcc/BSR displacement sizes, DBcc,
LINK/UNLK, RTS/RTD/RTR, bounded RTE frames, CCR/SR transfers and status/USP
privilege checks. Its MOVEC implementation reads/writes all eight MMU registers
on the supplied engine, preserving masks and the lack of implicit ATC flushing.
PTEST uses DFC and reports table-search status through MMUSR; PFLUSH variants
honor DFC privilege selection, both ATC banks and global qualification. For
undefined per-page PFLUSH DFC values, this implementation selects no entries.
The additional fixture passes 46,996 control/fetch/stack/MMU instruction cases.
Instruction encodings and semantics follow Motorola's
[Programmer's Reference Manual, section 6](https://www.nxp.com/docs/en/reference-manual/M68000PRM.pdf).

Mapped CHK.W/L and CMP2/CHK2 now share the checked bounds decoder, including
signed address-register comparisons, circular intervals and format-2 exception
records. MOVE16 shares its live-extension decoder and uses mapped scalar long
transfers for the aligned line. It snapshots source data before stores; failed
stores retain completed writes and do not commit postincrements. Its access
record describes the failed scalar transfer, not a complete hardware line-cycle
or format-7 writeback state. The expanded control fixture passes 101,224 cases.
Flat MOVE16 retains its whole-instruction/whole-span checks; 50,453 cases pass
in each interpreter/native mode.

`mapped-cpu.h` now exposes a bounded logical instruction-stream romaw. It
shares decoded integer and FPU dispatch, fetches each opcode exactly once,
preserves architectural ATC behavior across control writes and never reuses a
flat compiled block or synthetic return cache. Budget, eligible interrupt,
reported exception and unsupported-instruction stops are explicit; exception
delivery/restart remains caller-owned. This is an explicit backend, not a
switch enabling paging in ROMAW's native Toolbox/host-pointer paths.

Its 197-case stream fixture includes a guest that constructs page tables,
enables translation with MOVEC, accesses nonidentity data mappings, executes
PTEST/PFLUSHA and returns MMUSR. It checks different dispatch budgets,
cross-page loops, single-fetch FPU operations, self-modifying code, access and
alignment faults, interrupt stops and zero-budget/invalid arguments.

Ordinary exception entry is now available separately through
`syn68k_mapped_exception_enter`. Format-0/2/3 frames and vector reads use
supervisor data mappings. Master interrupts preserve the MSP frame and create
the format-1 ISP shadow; mapped RTE returns through both frames. Failed frame
or vector transfers retain completed writes and report their access metadata.
Failures while delivering vectors 2/3 are reported as double faults; other
delivery faults stop for the caller to handle. This API does not promise
hardware bus-cycle ordering or general format-7 restart/writebacks. Unsupported
formats are rejected before changing state. The stream fixture now passes
2,844 cases, including all TRAP vectors, stack-bank/CCR/trace-bit round trips,
cross-page stacks, physical failures at every frame field, vector failures,
translation failures and rejection without side effects.

Aligned opcode-fetch faults now have a restricted format-7 delivery path. It
requires a failed two-byte instruction-space read at the original instruction
PC, with no partial transfer, RMW or operand write. This precedes instruction
execution and needs no operand continuation. The frame supplies SSW/FA and
zero pending-writeback slots. A real guest handler in the expanded 3,127-case
stream fixture repairs its page descriptor through mapped memory, executes
PFLUSHA and RTE, then successfully executes the formerly faulted opcode. Both
page sizes, privilege roots, translation/physical faults and every CCR are
checked, along with every frame/vector failure and unsupported-frame guards.
The stream runner additionally certifies read faults only when registers, CCR,
SR and FPU state are unchanged and no operand store was attempted. Bus wrappers
forward the same physical requests and record attempted writes; they never
undo transfers. Aligned, nonpartial, non-RMW reads with this certificate may use
the same no-writeback format-7 path. Component steppers do not issue certificates.
MOVEM, MOVE16, RTE and FPU operand continuations remain explicitly excluded,
even if their register values happen to compare equal. The expanded 4,154-case
fixture exercises byte/word/long data reads and extension fetches with guest
page-table repairs, physical/translation failures, every CCR and both roots/page
sizes. Address-updating and store faults remain rejected. General restart,
pending writebacks and FPU/cache continuation are still unfinished.

Scalar final stores now have an explicit retirement path. The shared decoder
offers its calculated next PC and CCR without changing component-step failure
semantics. The stream runner retires an aligned, nonpartial, nonlocked final
store and publishes one pending writeback: WB1 for a physical operand bus error,
WB2 for a translation/table fault. The frame uses the original logical address,
memory-lane-aligned WB1 data or register-aligned WB2 data. The guest handler
must complete the writeback before RTE; the CPU does not repeat the instruction.
There is no asynchronous store buffer, cache push or multiple-store continuation
claim. See MC68040UM 8.4.6.3-8.4.6.7 and table 8-6.

The expanded 14,906-case stream fixture compares failed-store retirement with
successful execution for MOVE, automatic addressing, CLR/NEG/NOT, quick and
immediate arithmetic/logic, conditions, shifts and bit operations. Guest code
repairs the descriptor, reads WB1/WB2, restores DFC, completes the actual store
using MOVES and executes RTE. It checks flags, next PC, address updates, every
CCR/byte lane, both page sizes/privilege roots and physical/permission failures.
Watched physical writes establish exactly one successful completion.

Pre-execute read faults now restore speculative address-register updates when
data registers, CCR, SR, stack banks and FPU results are unchanged and no store
was attempted. This applies to ordinary predecrement/postincrement reads and
partial page-crossing reads; component steppers retain their old partial-state
contract. Format-7 FA carries the original scalar request, while the returned
access metadata still identifies the failing chunk and completed prefix. SSW
retains the original size/FC and distinguishes a later-page ATC fault (MA) from
a physical bus failure. Completed reads and descriptor history are not undone.
RTE restarts the original instruction, so automatic addressing updates once.

The instruction-local bus observes operand-read and descriptor read/update
callbacks separately from instruction execution. Callback changes to An or FPU
null state deny generic checkpoint rollback, even when normal FPU entry would
otherwise hide the final null-state difference. Other register, status, bank and
FPU results still use the complete checkpoint checks. Callback return values,
bytes, descriptor effects and live CPU state remain intact. Native RAM paths
without external callbacks need no such observation. This does not cancel RTE's
explicit live privileged-SP restart: its completed frame progress and callback
effects stay live, including a callback that relocates the active frame.

A grouped 31,648-case family exercises integer/FPU direct, automatic and
memory-indirect reads, operand/opcode/extension/descriptor callbacks, successful
and failed descriptor transfers, all An and stack banks, FPU null reversal,
both page sizes/privileges and all four dispatch/bus combinations. Unchanged
callbacks still allow owned EA rollback. Mutating callbacks preserve the
component-step fault state and unsupported delivery performs no bus access.
The family also runs through cold/warm persistent native execution.

The expanded 16,954-case stream suite adds actual guest repair/RTE recovery for
one-, two- and three-byte prefixes of split word/long reads, both automatic
addressing modes, all CCR values, both roots/page sizes and both failure types.
MOVEM, MOVE16, locked writes, RTE internal state and FPU continuations remain
outside this ordinary-read restart path.

FPU reads now also use this certificate when the only FPU state change is
entry's transition from null to non-null. The runner retains that transition
and completed bus reads, restores speculative address-register updates and
allows the guest handler to repair the page and execute RTE. Any changed
FPR/control/status/frame result, reverse null transition or attempted store

The 207,368-case stream group includes 1,728 guest repair/RTE cases for all
normal FPU source formats, every extended/double scalar fault position, direct,
postincrement and predecrement addressing, both null states, both page sizes

fault address, empty writeback slots and a successful retry with one final

Twenty-four injected callback-state cases verify that changed FPRs, controls,

Mapped RTE now consumes guest format-7 CP/CU continuations. It restores SR and
the stack bank, then reports the pending FPU exception before executing the
saved PC. CU selects vector 11/format 2; CP selects the saved FPU vector

remain available to the FPU handler. An invalid CP vector yields a format
error before popping the frame or restoring its SR. The 244,252-case stream

malformed-vector guards across checked/native dispatch and bus combinations.
Final aligned FPU move-out faults can also produce CP with a pending
writeback, as described below. Other CP/CU producers remain unfinished.

Format-7 RTE now reads only the required 14-byte header (offsets $0 through

Writeback slots belong to the guest handler and are not reread by RTE. The
245,732-case stream group adds 1,280 cases with an unmapped or rejecting tail,

source.

Mapped RTE frame-read faults now carry a restart marker at the current
privileged SP. The current frame has not been popped; earlier throwaway frames
and callback effects stay committed. The decoder offers this marker without
rolling back stack/status changes. A fault after a throwaway return to user
mode remains unsupported. The 256,012-case stream group includes 5,120 first-
frame and 5,120 privileged throwaway-progress guest page-repair/RTE retries,
24 callback-state retention cases and 16 user-progress guards. The remaining
frame stays intact and the new access-error frame is stacked below it.

Pre-execute locked data reads now use the ordinary read certificate when no
store was attempted and architectural results remain unchanged. LK, size, FC
and ATC/physical fault status are retained in the frame. Locked instruction-
fetch records remain rejected. The 280,608-case stream group adds 24,576
TAS/CAS/CAS2 guest page-repair/RTE cases across sizes, automatic addressing,
both CAS2 read positions, roots/page sizes, CCRs and nonresident/protected/
physical failures, plus 24 changed-FPU-state guards. Read counters preserve
earlier CAS2 bus activity through the handler and count the architectural
retry; watched stores complete once. Bus locking remains the embedding caller's
responsibility.

Final TAS/CAS writes and CAS2's second write now offer explicit locked-store
retirement. The runner validates the marker against RMW intent, commits completed
CCR/EA state, and buffers the failed store through WB1/WB2 with LK retained in
the SSW. The guest completes that store without repeating locked reads or CAS2's
first completed write. A CAS2 first-write fault additionally captures its second
operand's independently calculated address and value in the next writeback slot.
Its data function code follows callback changes, while its source value and
address remain those captured before the locked reads. Unaligned locked stores
remain unsupported. Component stepping retains its old flags until retirement.

An FPU move-out fault on its final scalar transfer, or its penultimate
longword for double/extended formats, can now
offer `Syn68kFPUStep.store_state = 1` with `store_next`. Component stepping
keeps its fault PC; the mapped runner independently validates the offer,
retires completed FPU/EA results without changing CCRs, and stacks one WB1 or
WB2 entry with the following PC. A captured following longword uses WB2 after
a physical fault or WB3 after a translation fault. The guest drains these slots
in order; earlier double/extended words stay committed. RTE resumes the following
instruction or dispatches CT trace. With a deferred numeric exception, the
runner instead sets CP and retains the original operand EA and pending FPU
busy frame. CP takes priority over CT; after writeback cleanup, RTE dispatches
the pending FPU vector with a format-3 EA. The FPU handler can FSAVE the busy
frame, clear it with FRESTORE and return normally. Faults before the final two
longwords and partially completed physical faults remain unsupported by this retirement path.

FScc can retire a faulted result byte through the same WB1/WB2 path. Condition
evaluation and address updates remain committed, including disabled BSUN status;
enabled BSUN still traps before evaluating the destination or attempting a store.
The guest completes the pending byte before RTE resumes the following instruction
or dispatches CT trace. There is no pending numeric post-instruction exception.

FMOVEM can likewise retire its final longword store or its final two
longwords. Earlier register and word stores remain committed. The
native transfer kernel captures the final word before a penultimate-word bus
callback; recovery retains callback changes to FPRs while completing the original
captured data. The guest drains WB1/WB2 or WB2/WB3 in order. Earlier FMOVEM faults use the certified abort/replay path below. Final/prefinal
physical faults can retire after successful subcycles.
Each following word also retains its own data function code after the failed
callback, so a privilege change can select a different mapping for the tail.
The failed word keeps its original SSW/writeback function code.

Control-register lists can retire faults on their last or penultimate
longword. Generated code records the selected register index before each store;
the fault exit checks that at most one selected register remains. Earlier words
and EA updates stay committed, and the actual failed value is buffered through
WB1/WB2. When one register remains, its value is sampled after the failed
callback, matching the next normal transfer, and buffered in the following slot.
Earlier control-list faults use the certified abort/replay path below.

Early control-list, FMOVEM, FSAVE and FMOVE.X word/longword faults can instead
abort and replay. The runner certifies all sixteen general registers, stack
banks, SR/CCR and FPU state against instruction entry, allowing the owned
non-null transition, captured numeric FPSR/FPIAR and an exact auto-update EA
change. Only that address register is restored. Other certified callback changes,
including reversal of non-null entry, deny replay without undoing their effects.

WB1 retains a physical-fault scalar and WB2 an ATC-fault scalar. Both retain the
whole original value and address; partial ATC transfers must end at a page
boundary and set MA, while physical subcycle failures keep ATC/MA clear. The
stacked PC remains the original instruction and no continuation bit is set.
After guest cleanup and RTE, the entire instruction runs again, repeating earlier
writes. The checkpoint includes saved FPU frame bytes, size and pending vector;
FSAVE leaves them intact until successful reexecution. FMOVEM retains its normal
2/2/4/4 extended-register transfer order, including zero padding. These are the
data-access abort and ordinary format-7 return rules in
[MC68040UM sections 8.2.1 and 8.4.6.7](https://www.nxp.com/docs/en/reference-manual/MC68040UM.pdf).
They do not retire unfinished work or introduce private continuation state.

Successful mapped FPU and MMU instructions report trace from their instruction-
entry SR. T1 traces every successful instruction in this boundary; T0 traces
FMOVEM (including the single-control-register aliases), FSAVE/FRESTORE, every
FDBcc, taken FBcc, MOVEC, PTEST and PFLUSH. A taken FBcc whose target equals
fallthrough still qualifies. Native conditional code records the taken event;
the runner does not infer it from a changed PC. Trace uses a format-2 frame
with the next PC and the address of the traced instruction. Operand/descriptor
callbacks can change the stacked live SR without changing entry eligibility.
These rules and exception priorities follow
[MC68040UM sections 8.2.6 and 8.3](https://www.nxp.com/docs/en/reference-manual/MC68040UM.pdf).
Forced, unimplemented and floating-point exceptions retain priority and leave
trace handling to the other exception's guest handler.

A retired FPU write fault carries CT when its entry SR requires tracing,
including T0 on the serializing forms. A checked pure-store abort instead
keeps its original PC and unchanged SR with no CT; its complete reexecution
reports trace normally. Callback changes to that SR still prevent abort
certification, so the runner cannot lose the original trace condition.

FSAVE can retire its last or penultimate longword for null, idle and pending exception
frames. Component stepping retains a faulted saved frame and offers
`store_frame_clear` separately. Only after validating the store candidate does
the stream runner clear saved-frame size/pending-vector state, matching successful
FSAVE without changing the retained frame bytes, FPRs or controls. The guest
drains the pending slots before returning. A following frame word is sampled
after the failed callback, before committing saved-frame cleanup. Earlier than
penultimate frame stores require the abort certificate. Partial final/prefinal
physical stores can retire with their full scalar retained in WB1.

Retired FPU offers include unaligned word/longword transfers. WB1 data is rotated into its memory bus lanes
as specified by MC68040UM table 8-5, including word and longword wraps; WB2/WB3
data stays register aligned. Guest cleanup reverses WB1 alignment before its
normal-width store. Earlier successful transfers remain committed. Completed
nonlocked integer candidates also permit unaligned words/longwords and partial
physical or second-page ATC writes. The runner commits their deferred CCR once,
uses instruction-entry SR for CT eligibility and preserves the callback's live
SR in the frame. Guest cleanup repeats no operand reads or address updates.
MOVES also offers its completed scalar, with instruction-entry T1/T0 trace.
Ordinary converted FC1/5 stores use WB1/WB2; alternate spaces 0/3/4/7 support
physical WB1 cleanup with TT=2, no translation and no extra tail. Unchanged
alternate reads likewise permit guest repair/RTE restart. The new grouped MOVES
coverage and guest SSW-derived DFC cleanup are detailed in the writeback contract.
Memory destinations of MOVE SR/CCR also offer their completed scalar,
preserving live callback CCR changes and the pre-callback captured write value.
Locked stores retain their existing alignment/progress restrictions.

A second-page ATC write fault can also retire after a first-page prefix has
completed. The access must report consistent progress at a page boundary and
an ATC fault without an operand bus error. The original scalar address remains
in FA/WB2A, and WB2D retains the whole original operand. Guest cleanup repairs
the second page and writes the full sized operand, repeating its completed
prefix explicitly; WB3 holds a following word when needed. This follows the
MA/ATC frame protocol and the full-width cleanup used by the
[Linux 68040 writeback handler](https://kernel.googlesource.com/pub/scm/linux/kernel/git/torvalds/linux/+/05e96e96a315fa49faca4da2aedd1761a218b616/arch/m68k/kernel/traps.c).
Physical scalar prefixes use WB1. Partial locked stores and integer decoders
without completed-store offers still require further work. See the linked
writeback recovery contract for current combined coverage.

## Faults while resuming a MOVEM

A checked opcode-fetch failure during a restored CM continuation now produces
an access exception with the saved effective address retained. Successful
exception delivery suspends the CPU's pending continuation so the new guest
handler executes normally. Its format-7 CM frame restores the continuation on
RTE. The grouped 51,322-case stream fixture checks this nested handler/return
path for the existing indexed and PC-relative MOVEM cases. A changed non-MOVEM
opcode still stops explicitly with the saved continuation retained.

## Native mapped MMU instructions

The x64 mapped CPU dispatches MOVEC, PTEST and PFLUSH through managed native
bodies in both JIT and persistent AOT mode. MOVEC uses fixed control-transfer
roots shared with the checked model; PTEST and PFLUSH use the closed MMU roots.
The generated code checks supervisor privilege before fetching a live MOVEC
command. Invalid selectors and access failures leave the native frame before
reporting their architectural exceptions. PTEST retains its diagnostic MMUSR
behavior rather than turning a failed probe into a CPU access exception.

The 19,417-case instruction fixture compares CPU state, MMU/ATC state, memory,
exception metadata and ordered bus traffic against checked execution while
forbidding host semantic helpers in the native path. It covers all control
selectors and registers, masks and stack banks, DFC combinations, both page
sizes, command-fetch faults, 32-bit PC wrap and descriptor callbacks that run
nested native code and evict the parent's cache entry. Cold/warm AOT checks
change selectors, register values, DFC and ATC contents between executions.
The closed control-transfer roots have an additional 42,756-case differential
group on Windows and Linux ASan/UBSan. The grouped mapped stream suite runs
802,092 cases across checked and native CPU dispatch.

This completes native MMU instruction dispatch through the mapped CPU bus.
The flat ROMAW path still rejects MMU enable writes until its Toolbox and
host pointer interfaces support paged guest memory. FPU memory forms now use
closed native mapped/flat bindings; the remaining format-7 continuation cases
described above require further work.
